# 2026-07-24 — Day 10

**Focus:** Instrument one real metric in the orchestrator, scrape it with Prometheus while running
real deploys, and see it in a Grafana panel.

**Studied:** prometheus_client metric types and when a Counter beats a Gauge, and how `rate()`
turns a monotonic counter into something worth graphing.
Sources: https://prometheus.github.io/client_python/,
https://prometheus.io/docs/concepts/metric_types/

**Did myself:** No `/metrics` existed at the start of the day. Added `orchestrator/metrics.py` with
`deployments_total`, a Counter labelled `result` and `environment`, incremented in
`create_deployment` on both the success path and the `DeployError` path, and a `/metrics` route
serving the registry. Labelled by `environment` rather than intent name to keep cardinality bounded.

A fresh process served only `# HELP` and `# TYPE` for the metric. After one real success deploy and
one real failure, the scrape showed `deployments_total{environment="dev",result="success"} 1.0` and
`deployments_total{environment="staging",result="failed"} 1.0`. The failure was real: I created a
Deployment outside Helm and then submitted an intent with that name, so Helm refused to adopt it
with an ownership metadata error. Ran Prometheus in a container scraping `host.docker.internal:8000`
every 5s and confirmed the target `health=up`, then Grafana with a provisioned data source and a
one-panel dashboard, `sum by (result) (rate(deployments_total[1m])) * 60`. Checked the query against
the Prometheus API before trusting the graph, generated two bursts of real deploy traffic, and
rendered the panel to a PNG. Tore the monitoring containers down and left the kind cluster running.
Thirty-four tests pass and `ruff check .` is clean.

**Got stuck on:** The panel showed `No data` instead of a flat line at zero before the first deploy.
`prometheus_client` does not create a child series until a label combination is used, so the scraped
page carried the metric's `# HELP` and `# TYPE` and no samples at all. Nothing was broken; there was
genuinely nothing to plot. Also spent a few minutes on Grafana refusing to start because the default
image-renderer token is rejected, and on a provisioned data source pointing at `prometheus:9090`
when the container was named `nf-prometheus`.

**Learned:** An absent series and a zero value look the same on a dashboard and mean different
things. An alert on "success rate below X" would not fire on a freshly restarted process, because
there is no series to evaluate rather than because the system is healthy. Separately, the counter
sits behind M1 validation, so a `422` intent never reaches it; `deployments_total` counts deploy
attempts that passed validation, not requests to `/deployments`.
