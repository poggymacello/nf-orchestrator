# 2026-07-14 — Day 2

**Focus:** Run the FastAPI app for real and document what actually happens, not the theory.

**Studied:** FastAPI's request/response basics and the ASGI spec.
Sources: https://fastapi.tiangolo.com/tutorial/first-steps/,
https://asgi.readthedocs.io/en/latest/introduction.html

**Did myself:** Ran `uvicorn orchestrator:app --reload --port 8000`, hit `GET /` (404, nothing
registered there) and `GET /healthz` (200, `{"status":"ok"}`) with curl. Edited the `/healthz`
handler to add a `version` field while the server was running, to see `--reload` in action.

**Got stuck on:** `--reload` logged `WatchFiles detected changes... Reloading...` but never
actually respawned the worker — curl kept returning the old response body. Killed the process and
started a plain `uvicorn orchestrator:app --port 8000` without `--reload`; that served the new
field immediately, confirming the code was fine and the reload mechanism was what failed. Reverted
the `version` field afterward since it wasn't a scoped change, just a reload probe.

**Learned:** The FastAPI app object can live in a package's `__init__.py`, and the uvicorn module
path (`orchestrator:app`) has to point at wherever that object is actually assigned, not at an
assumed `app.py`.
